\subsection{Детали реализации механизма в исходном коде}

\subsubsection{Виртуальный уровень и политики}

Одной из ключевых структур данных подсистемы управления памятью Linux является \texttt{vm\_area\_struct}. Она описывает диапазон пользовательской памяти, содержит информацию о его свойствах и семантике. Практически любая операция управления памятью в ядре начинается с обращения к соответствующему экземпляру \texttt{vm\_area\_struct}.

Одним из важнейших атрибутов данной структуры являются флаги (см листинг~\ref{lst:vm_area_struct}). Они представляют собой битовую маску, в которой каждый бит соответствует определённому свойству области памяти.

\begin{lstlisting}[
    style=normal,
    caption={Флаги виртуальной области памяти},
    label={lst:vm_area_struct}
]
/* include/linux/mm_types.h */

struct vm_area_struct {
    ...
	union {
		const vm_flags_t vm_flags;
		vm_flags_t __private __vm_flags;
	};
    ...
};
\end{lstlisting}

Для поддержки механизма репликации были добавлены два новых флага, отвечающих за репликацию таблиц трансляций и данных соответственно (см листинг~\ref{lst:vm_replica_flags}). Именно по ним и будет определяться поведение механизма репликации в отношении конкретной области памяти.

Установка флагов должна выполняться всякий раз, когда создаётся новая виртуальная область либо изменяются атрибуты уже существующей области, например, при обработке системных вызовов \texttt{mmap} и \texttt{mprotect}. Соответствующие изменения показаны в листинге~\ref{lst:vmflags_modify_replica}.

Помимо этого флаги репликации приходится синхронно обновлять существующим областям при изменении процессом политик репликации таблиц трансляций и/или данных. На листинге~\ref{lst:numa_mm_handle_table_replication} показан код для смен политик репликации таблиц с \texttt{All} на \texttt{Minimal} и с \texttt{None} на \texttt{Minimal}. Кроме обновления флагов подходящим виртуальным областям инициируются операции репликации и дерепликации таблиц трансляций. Код для остальных переходов между политиками устроен аналогичным образом и отличается лишь набором областей, состояние которых необходимо изменить.

/* mm/numa_user_replication.c */

/* called when table replication policy goes from All to Minimal */
static void dereplicate_all2min_pgtables(struct mm_struct *mm) {
	struct vm_area_struct *vma;
    ...
	do {
		unsigned long addr = vma->vm_start;
		struct vm_area_struct *next;
        ...
        /* clear VM_REPLICA_INIT and dereplicate
         * pgtables for not replica candidate vmas */
		if (numa_is_vma_replicant(vma) && !vma_might_be_replicated(vma)) {
			vm_flags_clear(vma, VM_REPLICA_INIT);
			...
			dereplicate_pgtables_pgd_range(&tlb, addr, vma->vm_end, ...);
		}
		vma = next;
	} while (vma);
    ...
}

static void numa_mm_table_replication_minimal(struct mm_struct *mm) {
	switch (get_table_replication_policy(mm)) {
    /* executed when table replication policy goes from None to Minimal */
	case TABLE_REPLICATION_NONE: {
		struct vm_area_struct *vma;
		MA_STATE(mas, &mm->mm_mt, 0, 0);

		mas_for_each(&mas, vma, ULONG_MAX) {
            /* set VM_REPLICA_INIT and replicate
             * pgtables for replica candidate vmas */
			if (vma_replica_candidate(vma)) {
				vm_flags_set(vma, VM_REPLICA_INIT);
				replicate_pgtables_vma(vma);
			}
		}
		break;
	}
	case TABLE_REPLICATION_MINIMAL:
		return;
	case TABLE_REPLICATION_ALL:
		dereplicate_all2min_pgtables(mm);
		break;
	}

	set_table_replication_policy(mm, TABLE_REPLICATION_MINIMAL);
}
\end{lstlisting}

Аналогичным образом реализовано изменение политики репликации данных. На листинге~\ref{lst:numa_mm_handle_data_replication} показаны переходы с \texttt{Lazy}/\texttt{All} на \texttt{None} и с \texttt{Lazy/None} на \texttt{All}. Вместе со сменой флагов выполняется репликация и дерепликация соответствующих физических страниц. Однако следует отметить, что при переходе с \texttt{None} на \texttt{Lazy} выполняется только обновление флагов, репликация данных осуществляется отложено при обработках \textit{NUMA hinting faults} (см главу~\ref{sec:Chapter3_data_repl_policies}).

\begin{lstlisting}[
    style=normal,
    caption={Установка флага репликации данных при смене политики},
    label={lst:numa_mm_handle_data_replication}
]
/* mm/numa_user_replication.c */

static bool numa_mm_data_replication_none(struct mm_struct *mm) {
	switch (get_data_replication_policy(mm)) {
	case DATA_REPLICATION_NONE:
		return true;
    /* executed when data replication policy
     * goes from Lazy/All to None */
	case DATA_REPLICATION_ON_DEMAND:
	case DATA_REPLICATION_ALL: {
		struct vm_area_struct *vma;
		MA_STATE(mas, &mm->mm_mt, 0, 0);

		mas_for_each(&mas, vma, ULONG_MAX) {
            /* deduplicate data and clear VM_REPLICA_COMMIT
             * for all has_replicas vmas */
			if (vma_has_replicas(vma)) {
				vma_start_write(vma);
				if (phys_deduplicate(vma,
						vma->vm_start, vma->vm_end - vma->vm_start))
					return false;
				__vm_flags_mod(vma, VM_NONE, VM_REPLICA_COMMIT);
			}
		}
		break;
	}
	}

	set_data_replication_policy(mm, DATA_REPLICATION_NONE);
	return true;
}

static bool numa_mm_data_replication_all(struct mm_struct *mm) {
	switch (get_data_replication_policy(mm)) {
    /* executed when data replication policy
     * goes from Lazy/None to All */
	case DATA_REPLICATION_NONE:
	case DATA_REPLICATION_ON_DEMAND: {
		struct vm_area_struct *vma;
		MA_STATE(mas, &mm->mm_mt, 0, 0);

		mas_for_each(&mas, vma, ULONG_MAX) {
            /* set VM_REPLICA_COMMIT and duplicate data
             * for all replica candidate vmas */
			if (vma_might_be_replicated(vma))
				vm_flags_set(vma, VM_REPLICA_COMMIT);
			if (vma_has_replicas(vma))
				phys_duplicate(vma,
                    vma->vm_start, vma->vm_end - vma->vm_start);
		}
		break;
	}
	case DATA_REPLICATION_ALL:
		return true;
	}

	set_data_replication_policy(mm, DATA_REPLICATION_ALL);
	return true;
}
\end{lstlisting}

\subsubsection{Физический уровень}
\label{sec:Chapter4_phys_layer}

Перед тем как перейти непосредственно к репликации/дерепликации физических страниц, будь то страницы с таблицами трансляций или страницы с данными, необходимо рассмотреть несколько вспомогательных сущностей физического уровня, введённых для нужд репликации.

Физическое адресное пространство разбито на страницы, каждая из которых в Linux имеет \texttt{page}-дескриптор~--- экземпляр структуры \texttt{page}, содержащий всю информацию о ней. Как и в случае виртуальных областей памяти, одним из основных атрибутов физической страницы, являются флаги (см листинг~\ref{lst:page})~--- они также представляют собой битовую маску, в которой каждый бит соответствует определённому свойству страницы.

\begin{lstlisting}[
    style=normal,
    caption={Флаги физической страницы},
    label={lst:page}
]
/* include/linux/mm_types.h */

struct page {
    unsigned long flags;
    ...
};
\end{lstlisting}

Такое архитектурное решение накладывает небольшое ограничение на репликацию данных, которые могут разделяться между несколькими процессами. Необходимо исключать ситуации, когда одна и та же страница с данными реплицирована в контексте одного процесса и не реплицирована в контексте другого (см рис.~\ref{fig:data_repl_err}), поскольку значение флага \texttt{PG\_replicated} является общим для страницы. Именно поэтому при репликации и дерепликации данных исходная страница никогда не переиспользуется в качестве страницы-реплики (см главу~\ref{sec:Chapter3_data_repl}), а страница-реплика~--- в качестве оригинальной страницы (см главу~\ref{sec:Chapter3_data_table_derepl}).

Рассмотрим теперь особенности реализации реплицированных таблиц трансляций. В Linux для таблиц уровней PMD и PTE ассоциированы собственные блокировки для сериализации их модификаций. Чтобы согласованно модифицировать таблицы-реплики, необходимо использовать общую для них блокировку~--- об этом уже шла речь в предыдущих главах. Для этого среди таблиц-реплик фиксируется одна \textit{мастер}-таблица, блокировка которой и используется. И чтобы иметь доступ к этой блокировке из контекста любой таблицы-реплики, в каждой из них хранится указатель на \textit{мастер}-таблицу.

Для указателя на \textit{мастер}-таблицу добавлено специальное поле в \texttt{ptdesc}-дескрипторе~--- структуре-алиасе \texttt{page}-дескриптора, содержащей поля специально для таблиц трансляций (см листинг~\ref{lst:master_table}). Новое поле добавлено в одно из существующих объединений, поэтому размер структуры остаётся неизменным, а с другими полями объединения оно не конфликтует, т.к. они используются только в архитектурах x86 и PowerPC, не в arm64. Первоначально каждая таблица является сама себе \textit{мастер}-таблицей, однако в процессе репликации соответствующие указатели обновляются.

\subsubsection{Репликация таблиц трансляций}

Репликация таблиц трансляций происходит в процессе обработки ошибок страниц, которые в Linux выполняются в два этапа:
\begin{enumerate}
	\item сначала по виртуальному адресу, привёдшему к ошибке, выполняется последовательный спуск по уровням иерархии таблиц трансляций с аллокацией недостающих таблиц;
	\item затем определяются и выполняются необходимые действия на уровне соответствующей PTE-записи и страницы с данными.
\end{enumerate}

Репликация таблиц целиком и полностью происходит на первом этапе. Для этого стандартные функции спуска по иерархии таблиц трансляций были заменены модифицированными версиями, которые помимо выделения отсутствующих таблиц выполняют их репликацию при необходимости (см листинг~\ref{lst:handle_mm_fault}).

На листинге~\ref{lst:replication_handle_pte_fault} приведён код функции \texttt{replication\_handle\_pte\_fault}, выполняющей репликацию PTE-таблиц. Возможны два варианта развития событий, различающиеся исходным состоянием PTE-уровня.
\begin{enumerate}
	\item\hypertarget{itm:table_repl_absent}{} PTE-уровень отсутствует и должен быть создан сразу в реплицированном виде.

	В этом случае выполняются следующие действия:
	\begin{enumerate}
		\item Создать и подготовить пустые таблицы-реплики. Подготовка включает:
		\begin{itemize}
			\item установку \texttt{PG\_replicated} флага всем таблицам-репликам;
			\item установку указателей на \textit{мастер}-таблицу~--- ей может быть любая из реплик;
			\item соединение таблиц в циклический односвязный список.
		\end{itemize}
		\item Захватить блокировку родительского PMD-уровня и убедиться, что репликация не была выполнена конкурентным потоком.
		\item Встроить PTE-таблицы-реплики в иерархию.
	\end{enumerate}

	\item PTE-уровень существует и представлен единственной таблицей, которую необходимо реплицировать.

	В этом случае необходимо:
	\begin{enumerate}
		\item Аллоцировать недостающие PTE-таблицы.
		\item Захватить PMD-блокировку родительского слоя и убедиться, что репликация не была выполнена конкурентным потоком.
		\item Захватить PTE-блокировку существующей PTE-таблицы~--- это необходимо для фиксации её состояния на время репликации, т.к. она уже встроена в иерархию и может одновременно использоваться другими потоками.
		\item Только после получения эксклюзивного доступа к существующей PTE-таблице можно приступать к подготовке таблиц-реплик. Подготовка включает все действия, перечисленные для \hyperlink{itm:table_repl_absent}{первого} случая, а также дополнительный этап~--- нужно скопировать содержимое существующей PTE-таблицы в остальные реплики. В качестве \textit{мастер}-таблицы в данном случае используется исходная PTE-таблица, поскольку именно её блокировка удерживается в момент репликации.
		\item Встроить оставшиеся таблицы в иерархию.
	\end{enumerate}
\end{enumerate}

\begin{lstlisting}[
	style=normal,
	caption={Репликация PTE-таблиц},
	label={lst:replication_handle_pte_fault}
]
/* mm/numa_user_replication.c */

static vm_fault_t replication_handle_pte_fault(struct vm_fault *vmf)
{
	int ret;
	struct mm_struct *mm = vmf->vma->vm_mm;
	struct ptdesc *pte_tables[MAX_NUMNODES];
	spinlock_t *ptl;

	/* true if PTE-level is absent or replicated */
	if (replicated_pte_level(vmf)) {
		if (!pmd_none(*vmf->pmd))
			/* PTE-level is not absent, therefore it is replicated.
			 * Nothing need to do, returning. */
			return 0;

		/* PTE-level is absent, we need to create and replicate it */

		/* Allocate and prepare replicated PTE-tables.
		 * Preparation involves:
		 * 1. setting PG_replicated flag;
		 * 2. setting master-table for tables-replicas;
		 * 3. connecting tables into cyclic linked list.
		 */
		ret = prepare_replicated_pte_tables(NUMA_NO_NODE, pte_tables, mm);
		if (ret)
			return VM_FAULT_OOM;
		/* acquire PMD-lock before modifying parent PMD-tables */
		ptl = pmd_lock(mm, vmf->pmd);
		if (unlikely(pmd_present(*vmf->pmd))) {
			/* Someone else has already replicated this level.
			 * Nothing else need to do, releasing and returning. */
			spin_unlock(ptl);
			release_replicated_pte_tables(NUMA_NO_NODE, pte_tables, mm);
		} else {
			/* Populate PMD-entries to point to replicated PTE-tables. */
			sync_replicated_pte_tables(NUMA_NO_NODE, pte_tables,
				vmf->pmd, mm);
			spin_unlock(ptl);
		}
	} else {
		/* the only PTE-table exists, we need to replicate it */

		struct page *table_page = pmd_pgtable(*(vmf->pmd));
		int pte_node = page_to_nid(table_page);

		pte_tables[pte_node] = page_ptdesc(table_page);
		/* Allocate remaining PTE-tables. */
		ret = prepare_replicated_pte_tables(pte_node, pte_tables, mm);
		if (ret)
			return VM_FAULT_OOM;
		/* acquire PMD-lock before modifying parent PMD-tables */
		ptl = pmd_lock(mm, vmf->pmd);
		if (unlikely(PageReplicated(table_page))) {
			/* Someone else has already replicated this level.
			 * Nothing else need to do, releasing and returning. */
			spin_unlock(ptl);
			release_replicated_pte_tables(pte_node, pte_tables, mm);
		} else {
			/* Acquire PTE-lock of existing PTE-table.
			 * Prepare replicated PTE-tables, it involves:
			 * 1. setting PG_replicated flag;
			 * 2. setting master-table to point on existing PTE-table;
			 * 3. connecting tables into cyclic linked list;
			 * 4. copy the contents of existing PTE-table to others.
			 * Populate PMD-entries to point to replicated PTE-tables.
			 */
			sync_replicated_pte_tables(pte_node, pte_tables,
				vmf->pmd, mm);
			spin_unlock(ptl);
		}
	}

	return 0;
}
\end{lstlisting}

Фаза сканирования состоит из двух этапов:
\begin{enumerate}
	\item На первом этапе выполняется обход виртуальных областей памяти и отбор тех из них, которые подлежат дальнейшему участию в механизме.

\subsubsection{Дерепликация таблиц трансляций и данных}

Дерепликация таблиц трансляций выполняется при ослаблении политики их репликации. В листинге~\ref{lst:numa_mm_handle_table_replication} показана функция \texttt{dereplicate\_all2min\_pgtables}, вызываемая при переходе политики с \texttt{All} на \texttt{Minimal}. Аналогичным образом функция \texttt{dereplicate\_all\_pgtables} используется при переходе с \texttt{All}/\texttt{Minimal} на \texttt{None}. Эти функции отличаются только множеством оперируемых виртуальных областей, однако обе используют общую функцию \texttt{dereplicate\_pgtables\_pgd\_range}, непосредственно выполняющую дерепликацию таблиц страниц в заданном диапазоне виртуальных адресов.

Функция \texttt{dereplicate\_pgtables\_pgd\_range} выполняет рекурсивный обход иерархии таблиц страниц и последовательно дереплицирует её уровни, начиная с наиболее нижних. На листинге~\ref{lst:dereplicate_pgtables_pte_range} показана функция дерепликации PTE-таблиц. Её работа состоит из следующих шагов: 
\begin{enumerate}
	\item в качестве единственной сохраняемой таблицы выбирается \textit{мастер}-таблица;
	\item записи родительских PMD-таблиц перенаправляются на выбранную \textit{мастер}-таблицу;
	\item выполняется обход остальных таблиц-реплик, их циклический список разрывается, а флаг \texttt{PG\_replicated} сбрасывается, после чего таблицы освобождаются;
	\item для \textit{мастер}-таблицы также разрываются связи списка и сбрасывается флаг \texttt{PG\_replicated}.
\end{enumerate}

Дополнительных сложностей, связанных с синхронизацией, в данном случае не возникает, поскольку дерепликация выполняется во время изменения политики репликации таблиц трансляций, которое происходит при эксклюзивном захвате адресного пространства процесса.

\begin{lstlisting}[
	style=normal,
	caption={Дерепликация PTE-таблиц},
	label={lst:dereplicate_pgtables_pte_range}
]
/* mm/numa_user_replication.c */

static void dereplicate_pgtables_pte_range(struct mmu_gather *tlb,
	pmd_t *pmd, unsigned long addr) {
	unsigned long offset;
	struct ptdesc *curr, *tmp;
	pmd_t *curr_pmd;
	pte_t *curr_pte;
	spinlock_t *lock;
	/* master-table is the only one that will remain */
	pgtable_t ptetable = ptdesc_page(
		page_ptdesc(pmd_page(*pmd))->master_table);

	/* nothing need to do if PTE table is not replicated */
	if (!numa_pgtable_replicated(page_to_virt(ptetable)))
		return;

	/* Populate PMD-entries to point to the master-table.*/

	lock = pmd_lock(tlb->mm, pmd); /* probably unnecessary */
	pmd_populate(tlb->mm, pmd, ptetable);
	for_each_pgtable_replica(curr, curr_pmd, pmd, offset)
		pmd_populate(tlb->mm, curr_pmd, ptetable);
	spin_unlock(lock);

	/* Release unneeded tables. */
	for_each_pgtable_replica(curr, tmp, curr_pte,
		page_to_virt(ptetable), offset) {
		/* destroy the cyclic linked list */
		cleanup_pte_list(ptdesc_page(curr));
		/* release the table (PG_replicated flag unsetting here) */
		pte_free_tlb(tlb, ptdesc_page(curr), addr);
		mm_dec_nr_ptes(tlb->mm);
	}

	/* destroy the cyclic linked list and
	 * unset PG_replicated flag for master-table */
	cleanup_pte_list(ptetable);
	ClearPageReplicated(ptetable);
}
\end{lstlisting}
